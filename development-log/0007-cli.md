# Development Log 0007 — Command-line interface (Phase 7)

- **Date:** 2026-07-25
- **Branch:** `feat/validation-and-summaries` (continuous alpha build)
- **Status:** Phase 7 complete. Five practical commands with documented exit
  codes. Resolves Q7.
- **Author:** Ron Finn

## 1. Objective

Turn the implemented Python API into a usable command-line tool, without adding
any capability the library does not already have.

## 2. Command surface (resolves Q7)

```
openauc version
openauc formats            [--json]
openauc inspect  INPUT     [--json]
openauc validate INPUT     [--readiness] [--json]
openauc convert  INPUT OUT [--overwrite] [--json]
```

`INPUT` is uniformly "an experiment directory, a data file, or an `.aucx`
archive" — the same dispatch `openauc.load` performs, so users never have to
tell the CLI which kind of input they have.

## 3. Exit codes

Stable, documented, and the reason the CLI is scriptable at all:

| Code | `ExitCode` | Meaning |
|------|-----------|---------|
| 0 | `OK` | Success; where validation ran, it passed |
| 1 | `VALIDATION_FAILED` | Structural validation reported an `ERROR` finding |
| 2 | `INPUT_ERROR` | Input unreadable, unparseable or unverifiable |
| 3 | `OUTPUT_EXISTS` | Output exists and `--overwrite` was not given |

Separating 1 from 2 is the load-bearing decision: "this file is not an
experiment" and "this experiment has a structural problem" are different
outcomes and a script needs to act differently on each. `OUTPUT_EXISTS` is
distinct from a general input error so a wrapper can decide whether to retry
with `--overwrite`.

## 4. Design decisions

**Domain errors never print a traceback.** `OpenAUCError` and its subclasses are
caught and rendered as a single `error: ...` line on stderr. A traceback would
be noise for a user whose CSV simply has a bad column. Unexpected exceptions are
deliberately *not* caught — a genuine bug should still be loud.

**`validate` checks archive integrity before structure.** For an `.aucx` input,
`validate_aucx` runs first; if the container is broken the command exits 2
without pretending to have examined the experiment. A corrupt archive is an
input problem, not a validation failure.

**`--readiness` is opt-in.** Structural validity is the common question, and
mixing readiness advisories into the default output would blur exactly the
distinction Phase 4 exists to draw. When requested, the readiness block is
labelled "metadata presence only" and includes the permanent
`scientific_suitability: not_assessed` entry.

**Every text output that could be mistaken for a verdict carries a disclaimer.**
`validate` ends with an explicit note that no claim is made about scientific
validity or data quality; `inspect` inherits the summary's existing note.

**`convert` accepts an archive as input.** Archive-in/archive-out is how a user
verifies and rewrites an archive, which the phase brief called for; it reuses
the same load dispatch, so it needed no special case.

**Imports inside command bodies.** `openauc.load`, `available_formats` and
`validate_aucx` are imported where used so `openauc --help` and `openauc
version` stay fast; the heavy model stack loads only when a command actually
needs it.

## 5. Tests

28 tests in `tests/cli/test_cli_commands.py`, using Typer's `CliRunner` plus two
real subprocess invocations:

Text and JSON output for every command; JSON parity with
`summary_data().to_dict()`; format listing including ids, suffixes, layouts and
limitations; help output; no-argument behaviour; success and every failure exit
code; malformed manifest; missing input; structural failure (a wide fixture with
a zero radius, giving `non_physical_radius`); corrupt archive detected via
checksum; overwrite refusal and `--overwrite`; non-`.aucx` output rejection;
archive round-trip through `convert`; and assertions that no output path ever
contains "Traceback".

Two of my own test bugs surfaced and were fixed rather than worked around: a
naive byte-replacement that did not actually corrupt a compressed payload, and a
round-trip equality check that ignored `imported_at` legitimately differing
between two reads of the same CSV.

## 6. Known limitations

- No `plot` subcommand — plotting stays a Python API; a CLI plot would need
  output-format, size and styling options that are not yet designed.
- No batch or glob input; one experiment per invocation.
- No `--quiet`; suppress with shell redirection.
- `convert` writes AUCX only. There is no AUCX → CSV path, and adding one would
  need a documented lossiness policy.
- `--json` output shape is stable per command but not schema-versioned.
